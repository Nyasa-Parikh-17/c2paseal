# Watermark and recovery

Content Credentials live in the file's metadata. Most social networks and
messaging apps strip metadata and re-encode the picture, so a copy usually
arrives *without* credentials. Recovery gets them back:

1. Before signing, embed an invisible **watermark** carrying a random
   64-bit ID.
2. Sign, recording the ID in a `c2pa.soft-binding` assertion.
3. Keep the manifest store in a **manifest store service** (`sealstore`),
   under the ID.
4. Later, for a copy without credentials: read the watermark, fetch the
   manifest by its ID, and verify it against the copy.

## The watermark

The [watermark](../watermark) module is written from scratch in Go. It
uses a DWT-DCT method with a 96-bit payload (the ID plus a CRC-32),
repeated about 42 times. Measured on four photos
([ROBUSTNESS.md](../watermark/ROBUSTNESS.md), regenerated by CI):

| Survives | Does not survive |
|---|---|
| JPEG re-compression down to quality 50 | **Any cropping**, even 2 % |
| Resizing, 50 % to 125 % | Screenshots with a window border (they shift the image) |
| Brightness, contrast, gamma, noise | Resizing to 50 % then JPEG 75 on a small (375 px) image |
| A tightly cropped screenshot | Rotation: not measured, and nothing in the design handles it |

There were no false detections. PSNR is about 49 dB: invisible at
normal size, though faint mottling can show when zooming into large flat
dark areas.

> **It is not a security feature.** The scheme is public: anyone with the
> code can read or remove the mark. It only links a copy back to its
> credentials. The credentials prove things; the watermark finds them.

```go
id, _ := watermark.NewID()
marked, err := wmfile.EmbedFile(jpegBytes, id, nil)
signed, err := c2paseal.SignAsset(marked, &c2paseal.SignOptions{
	Chain: chain, Signer: key,
	SoftBindings: []sign.SoftBinding{{Alg: watermark.SoftBindingAlg, Value: id.String()}},
})
```

## sealstore

[sealstore](../cmd/sealstore/README.md) is a self-hosted manifest store
(files on disk):

```sh
sealstore serve --dir ./stores --api-keys keys.txt --addr :8090
sealstore sign --cert chain.pem --key key.pem --in photo.jpg --out photo.signed.jpg \
  --store https://store.example.com --api-key "$KEY"
sealstore recover --store https://store.example.com --trust c2pa-trust-list.pem copy.jpg
```

- `GET /v1/manifests/{id}` is public. A manifest store holds nothing the
  signed file did not already carry.
- `PUT` needs an API key. The store checks that the manifest really
  records that watermark ID.
- It ships as a distroless container image, and every request is
  audit-logged.

## What a recovered result means

A recovered copy **never verifies as unchanged**. Its bytes differ from the
signed file's, so the hard binding fails, and the report says so. Recovery
succeeds when the watermark is read, the store has a manifest recording
that ID, and its signature validates. The answer is "these credentials
belong to the picture this copy came from", not "this copy is the original".

The web app's **Recover credentials** tab does the same in the browser. A
runnable version without a server:
[examples/watermark-recover](../examples/watermark-recover/main.go).
