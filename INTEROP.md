# Interoperability report

Generated by `go run ./interop` on 2026-11-11 14:00 UTC. Do not edit by hand: rerun the command.

Every JPEG and PNG fixture in `testdata/`, plus each unsigned fixture signed by C2paSeal (`c2paseal/…`, and `c2paseal+tsa/…` with an RFC 3161 time-stamp from a local test TSA), is validated by each tool in two trust modes:

- **default**: the tool's own default trust (C2paSeal and c2patool: no anchors; c2pa-mcp: its embedded C2PA trust list).
- **trusted**: the TEST ONLY root `testdata/pki/trust-anchors.pem` as signing and time-stamping anchor.

All signing uses the TEST ONLY PKI in `testdata/pki`, whose private keys are public.

## Setup

The external validators are separate programs, run as CLIs; nothing is added to `go.mod`. A tool that is not on PATH shows `-` and is never replaced by something else.

1. **Verify c2pa-mcp installs first.** Install it and check that it runs before generating the report:

   ```
   go install github.com/richardwooding/c2pa-mcp@v0.7.1
   c2pa-mcp verify --help
   ```

   If the install or the check fails, stop and fix it; do not substitute the `github.com/richardwooding/c2pa` library.
2. **Add c2patool as the second validator.** It is the Content Authenticity Initiative's official command-line tool (built on c2pa-rs), effectively the reference validator, and this project's oracle. Install a release from <https://github.com/contentauth/c2pa-rs/releases> (or `cargo install c2patool`), then check `c2patool --version`.
3. Run `go run ./interop`.

## How results are compared

Tools disagree on their native verdicts by design (c2pa-mcp reports `valid=false` for an untrusted signer, where c2patool reports `Valid`). So each tool's failure codes for the active manifest are reduced to one state with c2pa-rs's rule: any failure other than `signingCredential.untrusted` → **Invalid**; no failures and `signingCredential.trusted` → **Trusted**; otherwise **Valid**; no statuses at all (the tool exited with an error) → **error**. Two tools agree on a file when both the derived state and the set of failure codes match. Success and informational codes are listed per file but not compared.

**Summary:** 30 files × 2 modes = 60 checks; tools agree on 34, disagree on 26 (26 explained below, 0 unexplained).
