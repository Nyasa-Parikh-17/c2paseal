# C2paSeal — context for Claude Code

Pure-Go library for reading, verifying and **signing** C2PA Content Credentials in JPEG and PNG.
Pure-Go readers already exist (`richardwooding/c2pa`); the gap this fills is a CGO-free **signer**.

The work is split into phases in `PHASES.md`. Progress is tracked in `PROGRESS.md`.

## How to work in this repo

- Do **one phase per session**. Read `PROGRESS.md` first, then only the phase you were asked to do.
- When a phase is done, append to `PROGRESS.md`: phase number, date, what was built, test results, open issues.
- Phases marked **STOP — human gate** end with a report to the user. Do not start the next phase until they approve.
- If a phase's "Done when" checks cannot pass, stop and report what is failing and why. Do not weaken the check.

## Hard rules

1. **No CGO.** Every build and test runs with `CGO_ENABLED=0`.
2. **Dependencies are fixed:** `github.com/fxamacker/cbor/v2`, `github.com/veraison/go-cose`, `github.com/digitorus/timestamp`, plus the standard library. Ask before adding anything else. CLI uses the standard `flag` package.
3. **Bad input never panics.** Parsers return errors; `Verify` turns malformed or invalid files into C2PA failure status codes, not Go errors.
4. **`c2patool` is the oracle.** Files in `testdata/**/*.expected.json` are generated by `c2patool` and are never edited by hand to make a test pass. If our output disagrees with the oracle, our code is wrong until proven otherwise.
5. **Byte-exactness.** Container read/write must round-trip byte-for-byte. On the read path, keep the original CBOR bytes; never re-encode a claim and then hash or verify the re-encoded bytes.
6. **Reserve-and-backfill invariant.** When signing, the placeholder manifest and the final manifest must have identical byte lengths. Enforce this with a check in production code that returns an error, not only in tests.
7. **Scope is frozen:** JPEG + PNG, ES256, hard binding (`c2pa.hash.data`). No video/BMFF, no soft-binding watermarks, no remote manifests. Note scope-creep ideas in `PROGRESS.md` under "Future work" instead of building them.
8. The C2PA spec revision we target is pinned in `SPEC.md`. Use its field names.
9. Never claim "zero dependencies" or "the first Go C2PA library" in docs or comments.

## Layout

```
c2paseal.go            top-level Read / Verify / Sign
container/jpeg         APP11 segments
container/png          caBX chunk
container/jumbf        JUMBF box tree
manifest/              claim, assertion/, cose/
verify/                status codes, signature, chain, timestamp, hard binding
sign/                  builder, reserve, backfill
cmd/c2paseal           CLI
web/                   demo UI (net/http + embed)
testdata/              fixtures + oracle JSON
interop/               cross-tool harness
scripts/               fixture + PKI generation scripts
```

## Commands

```
CGO_ENABLED=0 go build ./...
CGO_ENABLED=0 go test ./...
go vet ./... && staticcheck ./...
go test -fuzz=Fuzz<Name> -fuzztime=60s ./container/...
c2patool <file> --detailed          # oracle output
```

## Style

- Small packages, exported API documented with GoDoc and a runnable `Example` where it helps.
- Table-driven tests over every fixture in `testdata/`.
- Errors wrap with context: `fmt.Errorf("jumbf: parse box at offset %d: %w", off, err)`.
