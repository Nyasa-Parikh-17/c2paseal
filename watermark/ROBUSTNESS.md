# Watermark robustness

Generated by `go run ./cmd/wmharness`; CI regenerates it and fails if it changes. Do not edit by hand.

Each image gets the same 64-bit ID with the default strength; each edit is applied to the watermarked image, then `Extract` must return exactly that ID. ✓ means recovered; ✗ means not (Extract reports no watermark: the CRC failed or the read was too weak). The number is how many of the 96 payload bits (ID + CRC-32) were read wrong at the best-fitting gain and offset; a ✗ with few wrong bits was close.

## Reading the results

- The mark lives in the image's coarse brightness pattern at a fixed working scale, so re-compression, resizing and mild noise leave it readable.
- Cropping shifts the pattern against the working grid, and colour changes move the brightness levels the bits are quantised to; those are the expected failures of this kind of watermark.
- Brightness, contrast and mild gamma changes are undone by the gain and offset search in `Extract`.
- A screenshot that includes the window border is a crop in disguise.
- Visibility: at about 49 dB the change is invisible at normal viewing size; zoomed in on large flat dark areas, a faint soft mottling can be seen.
- The scheme is public and unkeyed in practice: it is meant to link stripped copies back to their credentials, not to resist someone removing it on purpose.
