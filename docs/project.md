# Project status

C2paSeal is built in phases. The plan is in [PHASES.md](../PHASES.md),
and the build log, with test results for every phase, is in
[PROGRESS.md](../PROGRESS.md).

| Version | What it added |
|---|---|
| v0.1.0 | Read, verify and sign JPEG and PNG |
| v0.2.0 | Ingredients and history, remote manifests, C2PA 1.x, trust lists and revocation, batch mode |
| v0.3.0 | WebAssembly build and the web app on GitHub Pages |
| v0.4.0 | Key providers (AWS KMS, Google Cloud KMS) and the `sealsvc` signing service |
| v0.5.0 | WebP, HEIC and AVIF (the ISO BMFF layer) |
| v0.6.0 | Watermark, soft bindings, `sealstore`, credential recovery |
| v0.7.0 | HTTP middleware, GitHub Action, this documentation, examples |

Every change is listed in the [changelog](../CHANGELOG.md).

## What's next

- **Video:** MP4 and MOV, including fragmented MP4, then video in the web
  app and `sealsvc`, a full interop pass and the **v1.0.0** API freeze.
- **Waiting for a decision:** image features not yet approved for
  building are in [PENDING_APPROVAL.md](../PENDING_APPROVAL.md).
- **Longer term:** [FUTURE_SCOPE.md](../FUTURE_SCOPE.md).

## Compatibility

Before v1.0.0 the API can still change between minor versions. The
changelog says how. v1.0.0 will freeze it.

## Contributing and releases

- Run `CGO_ENABLED=0 go test ./...` in the core module and in each
  module with its own `go.mod`.
- New fixtures need their c2patool output, generated by `scripts/oracle`,
  never written by hand.
- Maintainers: [RELEASING.md](../RELEASING.md).
